# Sprint 3.2 検証報告

対象バージョン: 0.4.2
観測記録スキーマ: 9

## 実装済み

- MAX報告モードを粘性Level 1-3から分離
- MAX時の操作相関未確認通信を診断ログへ記録
- 内容変更2.5秒相関を維持
- 標準form操作2秒相関を追加
- 診断通信チップを800msで集約
- Coverage Manifestを設定画面へ追加
- 観測／縮約／設計上非観測／現在観測不能／未知残差を区別
- 任意通信権限の有無をCoverage Manifestへ反映
- チップ位置を上・左・下・右へ循環変更
- チップ位置をローカル設定へ保存
- チップ本体の操作透過を維持
- schema 9と閉じた相関カテゴリをプライバシー境界へ追加

## 静的検証

この生成環境では、TypeScript 5.8.3と一時的なChrome API型スタブを用いて、`src/**/*.ts`および`tests/**/*.ts`のstrict type checkを通過させた。

正式な依存関係を使う`npm ci`は、実行環境の内部npmレジストリに一部パッケージが存在せず完走しなかった。そのため、次は利用者環境での最終関門である。

```powershell
npm.cmd run format
npm.cmd run check
```

## 手動確認が必要な項目

- Chrome実型定義下での`onBeforeSendHeaders` listener型整合
- MAXの相関なし通信が診断ログへ入ること
- 標準form操作後のfetch/XHR相関
- 通信バーストのチップ集約
- 複数iframeでのMAX診断表示量
- チップ移動ボタンが入力欄への通常クリックを過度に遮らないこと
- ブラウザ再起動後のチップ位置保持
- MAX切替後の対象ページ再読み込み

## 観測責任上の注意

MAXは「すべてを観測する」モードではない。現在の権限、通信フィルター、Chrome API、content scriptの観測面で報告可能な範囲を最大化する。

`no_correlated_user_operation`は、利用者操作がなかったことを意味しない。DSSIが現在相関対象にしている内容変更または標準form操作を確認しなかったことだけを示す。

保存Cookie、ページ内部メモリ、確立済み通信路の個別メッセージなどは、Core Aでは観測経路へ接続しないか、現在の仕組みでは観測できない。Coverage Manifestはその差を表示する。
