## Sprint 3へ進む前の判断

理解回収により、DSSIの中核は「何を検出するか」だけでなく、「検出できたもののうち何を持ち帰らないか」にあると再確認した。

分類には、DOM属性や意味的文字列を一時参照する場合がある。通信メタデータ観測では、ブラウザAPIが完全URLをコールバックへ渡す。このためSprint 3は、通信機能の追加より先に、取得、縮約、相関、保存、利用者明示保存を別位相として定義する必要があった。

## 方針転換

当初の製品ロードマップでは、通信メタデータ技術スパイクは後段に置かれていた。実装理解と保存境界の検討が進んだため、現行開発ロードマップではSprint 3へ前倒しした。

これは通信監視をDSSIの主機能へ昇格させる変更ではない。Network Observerは引き続き補助観測であり、DOM上の早期接触認識がCore Aの主戦場である。

## 採用した方式

ページ実行領域でfetchやXHRをmonkeypatchせず、Chromeの任意`webRequest`権限を採用した。

理由:

- ページJavaScriptを変更しない
- ブラウザAPI由来の観測として区別できる
- 権限を利用者が明示的に追加・削除できる
- request bodyを要求しない構成を明示できる

## 実装した境界

### データライフサイクル

- 一時生観測材料
- 一時相関状態
- 縮約済み安全メタデータ
- 保存可能ObservationRecord
- 将来の利用者明示保存記録

を分離した。

### 閉じた保存スキーマ

Privacy Safe Loggerを、禁止語だけを見る方式から、許可項目を閉じる方式へ強化した。

- 未知項目を拒否
- ネストしたオブジェクトを拒否
- 予定外配列を拒否
- host欄のpath/query/credentials混入を拒否
- network payload状態を`not_requested`へ固定

### 通信相関

入力面操作から2500ms以内に、同一tab / frame / document（document ID取得時）で観測された`xmlhttprequest`または`ping`通信開始だけを記録する。

これは入力内容送信の証明ではなく、時間近接記録である。

## 新たに明確になったこと

1. 「直接観測」は一種類ではない。DOMイベント受信とブラウザ通信API受信は、別の観測面として区別する必要がある。
2. 「取得しない」と「保存しない」は別である。request bodyは未要求だが、完全URLはAPI入力として一時取得されるため、即時縮約と非保持を明示する必要がある。
3. パージはメモリの物理消去保証ではなく、処理局面を越えて参照を保持せず、永続化可能経路へ渡さない保証として定義すべきである。
4. 将来の証拠保護は、通常ログへ完全URLを足すのではなく、利用者明示保存という別境界にすべきである。

## 次の理解課題

- optional permissionsの付与・削除経路を確認する
- Content Script、Service Worker、storageの三重検査をコード上で追跡する
- ブラウザ統合テストの設計を検討する
