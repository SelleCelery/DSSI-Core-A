# DSSI Core A 開発記録 v0.4.6

## 対応Sprint

Sprint 3.4

## 主題

ドメイン別観測表示とログ保存境界

## 背景

Sprint 3.3系で通信パルスを実際のサイトへ適用すると、利用者は初見のhostnameでは表示密度を高くし、通信の時間配置や外部接続を確認した後、日常利用では表示負荷を下げると考えられた。

ただし、通信表示を減らす操作が、パスワード・決済情報・個人情報など粘性由来の注意表示まで消すことは許容できない。また、ログを保存する場合、DSSIが観測した一次記録と、その記録が成立した設定・観測範囲を切り離してはならない。

## 設計判断

### 表示プロファイルは信頼判断ではない

hostname別に保存するのは表示密度です。安全、危険、信頼、許可、評価は保存しません。

```text
HostDisplayProfile
  = 観測結果の見せ方
  ≠ trust / safety / allow list
```

### hostname単位

Sprint 3.4では`location.hostname`の完全一致を単位としました。登録可能ドメイン単位の自動統合は、役割の異なるサブドメインへ同じ設定を誤適用する可能性があるため行いません。

### 注意チップの独立

通信パルスと通信説明チップは減らせますが、粘性注意チップは別経路とし、透明度も固定しました。

### 設定スナップショット

現在設定を過去ログへ遡及適用しないため、schema 10から各記録へ`settingsSnapshotId`を付けました。取得できない旧記録は、exportで`partial`または`unavailable`と明示します。

### ログは一次観測記録

DSSIログはブラウザ通信のraw packetではありません。URL縮約、本文非観測、閉じた分類など、観測時点ですでにDSSIの境界処理を経ています。

したがって保存時の原則は、次です。

> 観測時の縮約は明示し、保存時には新たな集約・判定・補完を加えない。

全時系列を作るための選択と時刻整列だけを行い、それをexport metadataへ明記しました。

### 完全性は未提供

v0.4.6は暗号化、署名、ハッシュ検証、書き込み禁止を提供しません。単純な同梱ハッシュだけでは、意図的な改変者が内容とハッシュを同時に変更できるため、強い完全性保証にはなりません。

ログを守る技術は、同時に第三者監視、査定、責任追及、強制提出を強める可能性があります。将来の完全性・暗号化実装は、鍵管理だけでなく、開示・削除・検証・強制利用の境界と一緒に設計します。

## 実装内容

- DOM／webRequest色の独立選択
- マゼンタ／シアン／イエロー／無色
- 通信パルス不透明度 100／80／60／40%
- hostname別表示プロファイル
- HUDからの表示・説明・色・不透明度・位置の自動保存
- hostname profileの解除
- 初回観測hostnameの表示
- 90日経過profileの再確認契機
- 注意チップと通信表示の分離
- schema 10とsettings snapshot
- JSON／CSVログ保存
- 全ログ／現在表示中
- CSV-only用context JSON
- Coverage Manifestと利用境界の同梱
- 保存後の完全性未提供の明示
