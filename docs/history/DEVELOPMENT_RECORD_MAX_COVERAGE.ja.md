# DSSI Core A 開発記録｜MAX Coverage

## Sprint 3.2の判断

Sprint 3.1は、フォーカスを通信相関から外し、内容変更と通信開始を時間相関させた。これにより意味の精度は上がったが、内容変更から長時間後に送信する場合や、ページ側が利用者操作と無関係に行うリアルタイム通信を扱いにくかった。

Sprint 3.2では、検出力を一つの曖昧な相関へ戻さず、観測事実を三経路へ分けた。

1. 内容変更に近接した通信
2. 標準form送信操作に近接した通信
3. 相関可能な利用者操作を確認していない対象通信

第三経路はMAX報告モードだけで診断ログへ出す。これは意図外送信、自動送信、入力内容の送信を判定するものではない。

## MAXの位置づけ

MAXはLevel 4ではない。粘性は判断介入の強さを表すLevel 1-3のまま維持する。MAXはDSSI自身の報告責任を前景化する別軸である。

MAXでは、観測可能な診断事象だけでなく、DSSIが見ないもの、見えないもの、未知として残るものを設定画面へ返す。

## 権限拒否としての非観測

保存Cookieやページ内部メモリは、追加権限や侵襲的なページ注入によって接触可能性が高まる。しかし、観測能力の増加が利用者の主権を損なう場合、Core Aはそのインターフェイスへ接続しない。

これは機能不足として隠すのではなく、Coverage Manifestで「設計上、観測しない」として表示する。

## チップ位置

半透明チップは、入力欄と重なると判断支援から妨害へ転じる。チップ本体の`pointer-events: none`は維持し、右上の小さな移動ハンドルだけをクリック可能にした。

位置は上、左、下、右の四分類だけを保存する。座標追跡は行わない。
